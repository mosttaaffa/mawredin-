# الطوارئ: لو خدمة وقفت — النقل والاستعادة

التطبيق متقسم 3 حاجات مستقلة، وكل واحدة ليها بديل:

| الجزء | فين دلوقتي | ممكن يتنقل لـ |
|---|---|---|
| الواجهة (ملفات ثابتة) | Cloudflare Pages / GitHub Pages | أي استضافة ملفات ثابتة: Netlify، Vercel، GitHub Pages، Firebase Hosting، سيرفر عادي، أو الكمبيوتر بتاع المحل |
| البيانات + الدخول + الصور | Supabase (مجاني) | مشروع Supabase تاني، أو Supabase على سيرفرك/الـ NAS (Docker)، أو السيرفر المحلي في `local-server` |
| النسخ الاحتياطي | مستودع GitHub خاص (`mawredin-backups`) | أي مكان: الملفات مشفرة ومتنزّلة كـ Releases — نزّلها واحفظها على الكمبيوتر/الـ NAS/فلاشة |

**مفيش خدمة مجانية مضمونة للأبد** — عشان كده كل جزء معمول يتنقل من غير ما يعتمد على التاني.

---

## 1) لو الاستضافة (Cloudflare) وقفت
الواجهة مجرد ملفات. أي استضافة تانية:
```bash
node tools/build-dist.mjs     # بيطلع فولدر dist
```
- **Netlify**: app.netlify.com ← Add new site ← Deploy manually ← اسحب فولدر `dist` (ملف `_headers` بيشتغل عليه زي ما هو).
- **Vercel**: vercel.com ← New Project ← ارفع/اربط المستودع ← Output Directory = `dist`، Build Command = `node tools/build-dist.mjs`.
- **GitHub Pages**: مجاني بس للمستودعات **العامة** — ممكن مستودع عام فيه محتوى `dist` بس (مفيهوش أسرار أصلًا).
- **الكمبيوتر بتاع المحل**: `cd local-server && npm install && npm start` بيعرض التطبيق على `http://localhost:3000` (ومن الموبايلات على نفس الواي فاي).

بعد النقل: ضيف الرابط الجديد في Supabase ← Authentication ← URL Configuration، وعلى الرابط القديم (لو لسه شغال) حط `movedTo` في `config.js` (شوف «النشر على Cloudflare.md» ← خطوة 5).

## 2) لو مشروع Supabase اتوقف (Paused)
الخطة المجانية بتوقف المشروع لو مفيش استخدام أسبوع. **البيانات مبتتمسحش.**
- التطبيق بيقولك «السيرفر متوقف» في الإعدادات ← النسخ الاحتياطية.
- الحل: supabase.com ← المشروع ← **Restore project** (دقايق). العمليات اللي اتسجلت على الموبايل وقت التوقف محفوظة عليه وبتتبعت لوحدها لما يرجع.
- الوقاية: النسخ الاحتياطي اليومي (GitHub Actions) بيستعلم من قاعدة البيانات كل يوم.

## 3) لو Supabase نفسه بقى مش متاح / غيّر الخطة المجانية
### أ) مشروع Supabase جديد (نفس الخدمة، حساب أو منطقة تانية)
1. اعمل مشروع جديد ← SQL Editor ← **لا تشغّل setup.sql** (النسخة فيها كل حاجة).
2. من الكمبيوتر (محتاج `gh`, `gpg`, `psql`/`pg_restore` 17, `python3`) جوه مستودع `mawredin-backups`:
   ```bash
   export BACKUP_PASSPHRASE='كلمة سر النسخ'
   # اختبار الأول على قاعدة فاضية منفصلة:
   bash scripts/restore.sh daily-YYYY-MM-DD 'postgres://postgres:pass@localhost:5432/restore_test'
   # الاستعادة على المشروع الجديد (بيطلب تأكيد مكتوب):
   SUPABASE_DB_URL='رابط المشروع الجديد' bash scripts/restore.sh daily-YYYY-MM-DD "$SUPABASE_DB_URL" --production
   # الصور:
   SUPABASE_URL=https://الجديد.supabase.co SUPABASE_SERVICE_KEY=... python3 scripts/storage.py restore
   ```
3. مكان الصور (bucket `attachments` الخاص) وصلاحياته بيتعملوا لوحدهم مع خطوة الاستعادة (`scripts/storage-setup.sql`) قبل رفع الصور.
4. غيّر `config.js` في مستودع التطبيق (`url` و`key` = Publishable key الجديد) ← push ← بيتنشر.
5. **الحسابات (الإيميل وكلمة السر) مش جوه النسخة** — كل واحد يعمل حساب تاني بنفس الإيميل؛ الصلاحيات (members) راجعة من النسخة فهيدخل على بياناته على طول.
6. حدّث Secrets بتاعة مستودع النسخ (`SUPABASE_DB_URL`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`) للمشروع الجديد.

### ب) Supabase على سيرفرك أو الـ NAS (من غير أي اشتراك)
Supabase مفتوح المصدر: supabase.com/docs/guides/self-hosting/docker — بيشتغل بـ Docker. بعد التشغيل اتبع نفس خطوات (أ) بالرابط بتاعه.

### ج) طوارئ فورية من غير نت خارجي: السيرفر المحلي
`local-server` بيقلّد Supabase بالكامل (دخول + جداول + صور + نفس الصلاحيات) على أي كمبيوتر فيه Node.js. مناسب لو محتاج تشتغل النهارده لحد ما تجهز بديل أونلاين.

### د) PostgreSQL عادي (Neon وغيره)
النسخة `pg_dump` قياسية وبتترجع على أي PostgreSQL 15+ (`scripts/stub.sql` بيجهز الحاجات الخاصة بـ Supabase). لكن التطبيق محتاج كمان الدخول (Auth) وواجهة الجداول (REST) والصور — فـ Postgres لوحده **ينفع كأرشيف/تقارير**، والتشغيل الكامل محتاج (أ) أو (ب) أو (ج).

## 4) لو GitHub وقف
- الكود: نسخة كاملة على الكمبيوتر (`git clone`) — اعمل clone كل فترة واحفظه على الـ NAS.
- النسخ الاحتياطي: نزّل آخر Releases من `mawredin-backups` كل شهر على الكمبيوتر/الـ NAS (`gh release download daily-YYYY-MM-DD`).
- كمان من جوه التطبيق: الإعدادات ← النسخ الاحتياطية ← **نسخة يدوية** (ملف `.mawbak` مشفر بيتحفظ على الموبايل/الكمبيوتر) — مستقلة عن GitHub تمامًا.

## 5) لو حد مسح Safari / ضاع الموبايل
- كل البيانات على السيرفر؛ الموبايل الجديد بيحمّلها بعد تسجيل الدخول.
- الخطر الوحيد: عمليات اتسجلت من غير نت وما اتبعتتش. التطبيق بيعرض عددها في الإعدادات ← النسخ الاحتياطية («عمليات على الموبايل لسه ما وصلتش») — خليها صفر قبل أي مسح أو تغيير موبايل.
- «تسجيل الخروج» بيعرض اختيار حفظ العمليات اللي ما اتبعتتش في خزنة مشفرة على الجهاز.

## مراقبة الحدود المجانية
الإعدادات ← النسخ الاحتياطية ← «استهلاك الخطة المجانية»: حجم قاعدة البيانات (من 500 ميجا)، الصور (من 1 جيجا)، المستخدمين. الرئيسية بتعرض تنبيه لما أي حد يوصل 70%، أو لو النسخ التلقائي وقف أكتر من يومين.
السحب الشهري (5 جيجا) بيتشاف من لوحة Supabase ← Usage.

## اختبار الاستعادة دوري
كل نسخة يومية بتتجرب استعادتها لوحدها في GitHub Actions على قاعدة منفصلة (بتقارن عدد السجلات وأرصدة الموردين والشيكات والموظفين والقروض والمبيعات). مرة كل كام شهر: جرّب بنفسك خطوة 3(أ) على قاعدة فاضية على الكمبيوتر.
